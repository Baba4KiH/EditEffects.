# ee. — сайт и отправка заявок в Telegram

Сайт продолжает работать на GitHub Pages. Пока в `form-config.js` указан пустой `endpoint`, форма копирует заявку в буфер обмена. GitHub Pages не запускает серверный обработчик.

## Проверить реальную доставку сейчас, без покупки хостинга

1. Установите Node.js 22 или новее. Скачайте репозиторий и откройте терминал в его папке.
2. Создайте локальный файл `.env`, скопировав `.env.example`. Заполните только у себя:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_из_BotFather
   TELEGRAM_CHAT_ID=число_из_message.chat.id
   HOST=127.0.0.1
   PORT=3000
   ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
   ```

3. Нажмите Start в чате со своим ботом, если ещё не сделали этого.
4. Выполните `npm start`. Установка npm-пакетов не нужна: внешних зависимостей нет.
5. Откройте **http://localhost:3000**, заполните форму тестовыми данными, отметьте согласие и нажмите «Запланировать проект».
6. Проверьте получение сообщения в Telegram. Подтверждение на сайте появляется только после успешного ответа Telegram с идентификатором сообщения. Для остановки сервера нажмите Ctrl+C.

При локальном запуске сервер сам отдаёт конфигурацию с `/api/brief`. Менять публичный `form-config.js` для этого не нужно. Тестируйте форму именно на localhost, а не на опубликованной странице GitHub Pages.

**Не публикуйте `.env`, токен и заполненные скриншоты настроек.** `.env` добавлен в `.gitignore`, сервер не раздаёт его по HTTP. Не переносите `.env` в статический каталог хостинга. `TELEGRAM_CHAT_ID` задаётся на сервере; посетитель не может выбрать адресата.

## Если форма сообщает об ошибке отправки

В терминале **из папки проекта**, где лежит `.env`, выполните:

```sh
npm run telegram:check
```

Команда читает локальный `.env`, проверяет токен через `getMe` и доступность настроенного получателя через `getChat`. Она не отправляет сообщения, не читает переписку и не печатает токен, chat ID или исходные ответы Telegram. При ошибке выводит безопасный код и подсказку. Этот вывод можно прислать для диагностики; содержимое `.env` присылать не нужно.

Для проверки реальной доставки **одного тестового сообщения в чат из TELEGRAM_CHAT_ID**:

```sh
npm run telegram:test
```

Успех выводится только после подтверждения Telegram. Проверьте сообщение в нужном чате, затем запустите `npm start`, откройте `http://localhost:3000` и отправьте бриф через форму. Обновления кода требуют остановить старый сервер (Ctrl+C) и запустить его заново; после изменения `.env` тоже нужен перезапуск. Если переменные уже заданы в окружении терминала, Node использует их вместо значений `.env`: проверьте локально, что старые переменные не перекрывают настройки.

| Код | Что проверить |
| --- | --- |
| `TELEGRAM_NOT_CONFIGURED` | Обе переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` заполнены в `.env` в папке запуска. |
| `TELEGRAM_TOKEN_INVALID` | Токен из BotFather, без префикса `bot` и адреса API; после изменения перезапустить сервер. |
| `TELEGRAM_CHAT_NOT_FOUND` | Нажать Start у **этого** бота; для личного чата нужен числовой ID своего пользователя, не ID бота и не @username. |
| `TELEGRAM_FORBIDDEN` | Бот разблокирован; в группе/канале добавлен и имеет право отправки. |
| `TELEGRAM_CHAT_MIGRATED` | В `.env` указан новый ID супергруппы. |
| `TELEGRAM_NETWORK` / `TELEGRAM_TIMEOUT` | Доступ Node.js к `api.telegram.org`, DNS, VPN, firewall. Работа приложения Telegram сама по себе не подтверждает доступность API из Node.js. При таймауте проверить чат до повторной отправки. |
| `TELEGRAM_RATE_LIMIT` | Подождать перед повтором. |

Если проверка Telegram успешна, а форма сообщает, что не получила ответ сервера, убедитесь, что открыли страницу от `npm start`, а не файл `index.html`, Live Server или GitHub Pages. Сообщите точный новый текст ошибки формы и результат `telegram:check`.

## Автоматические проверки

```sh
npm test
```

Проверки используют подменённый ответ Telegram и не отправляют настоящие сообщения. Проверяются полезная нагрузка, ошибки и недоступность Telegram, Honeypot, согласие, лимиты размера полей и тела запроса, CORS, ограничение частоты, состояние кнопки и сохранение режима копирования для Pages. Успех этих проверок не заменяет проверку доставки в ваш чат по инструкции выше.

## Как включить на GitHub Pages до переезда сайта

Нужен отдельный публичный HTTPS-адрес сервера (временный сервер тоже подходит). Один локальный обработчик на вашем компьютере недоступен посетителям GitHub Pages.

1. Разместите Node.js-обработчик на сервере, задайте токен и chat ID в его секретных переменных окружения.
2. В `ALLOWED_ORIGINS` сервера добавьте точный origin сайта, например `https://baba4kih.github.io` (без пути `/EditEffects.` и без завершающего `/`). При собственном домене укажите его origin. Локальные адреса оставьте только если нужны.
3. В публичном `form-config.js` укажите **только** адрес обработчика:

   ```js
   window.EE_FORM_CONFIG = { endpoint: 'https://YOUR-BACKEND.example/api/brief' };
   ```

4. Проверьте отправку с опубликованного сайта. Бот не требует настройки Telegram webhook или постоянного опроса `getUpdates` для отправки уведомлений.

## Перенос на хостинг

Можно разместить весь сайт вместе с обработчиком: `npm start` обслуживает только перечисленные публичные файлы и `/api/brief`. Сервер слушает `127.0.0.1` по умолчанию. Для контейнера может понадобиться `HOST=0.0.0.0`, для публикации — HTTPS через платформу или reverse proxy.

Защита включает серверную проверку Honeypot и согласия, JSON до 16 КБ, ограничения длины и 5 запросов в минуту с одного IP. Лимит хранится в памяти одного процесса и сбрасывается при перезапуске. Заголовки `X-Forwarded-For` не считаются доверенными: за reverse proxy лимит применяется к адресу прокси; до публичного запуска настройте ограничение по реальному IP на прокси/платформе. CORS не заменяет защиту от ботов.

Повторная отправка автоматически не выполняется: при сетевом таймауте Telegram мог уже принять заявку. Поля формы сохраняются, пользователь может попробовать снова; в таком случае возможно повторное сообщение.

Политика и согласие пока содержат заглушки по решению владельца сайта. Проверка галочки и отметка времени в сообщении не являются системой юридического учёта согласий. Перед приёмом реальных данных обновите документы с учётом фактического способа обработки и доставки в Telegram.
