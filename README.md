# ee. — сайт студии видеомонтажа

Статический сайт на HTML, CSS и JavaScript с Node.js-обработчиком заявок в Telegram. Внешних npm-зависимостей нет.

## Структура

- `index.html`, `styles.css` — страница и оформление.
- `form.js`, `form-config.js` — форма и публичный адрес API.
- `server/` — локальный сервер, Telegram API и диагностика.
- `test/` — автоматические проверки без реальных сообщений.
- `consent.html`, `privacy.html` — страницы документов (пока заглушки).
- `_config.yml` — исключение серверных файлов, тестов и документации из публикации GitHub Pages.

## Локальный запуск

Нужен Node.js 22 или новее. Откройте терминал в папке проекта, скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Для личного чата нужен числовой ID получателя, не ID бота и не @username. Нажмите Start в чате с этим ботом.

```sh
npm start
```

Откройте http://localhost:3000. Локальный сервер сам задаёт `/api/brief`; менять `form-config.js` не нужно. Заполните форму, отметьте согласие и проверьте получение заявки. Для остановки нажмите Ctrl+C. После изменения кода или `.env` перезапустите сервер.

`.env` хранится только локально и игнорируется Git. Токен и получатель задаются на сервере; не добавляйте их в браузерные файлы. Уже заданные переменные окружения терминала имеют приоритет над `.env`.

## Проверки и диагностика

```sh
npm test
npm run telegram:check
npm run telegram:test
```

- `npm test` проверяет форму, сервер и ошибки с подменённым Telegram API; сообщения не отправляются.
- `telegram:check` проверяет токен и доступ к настроенному чату, не отправляет сообщения и не читает переписку.
- `telegram:test` отправляет одно тестовое сообщение в чат из `.env`. Успех выводится после подтверждения Telegram; получение проверьте в самом чате.

Диагностика не печатает токен, chat ID или исходные ответы Telegram. При сетевом таймауте сначала проверьте чат: повторная отправка может создать дубль.

| Ошибка | Действие |
| --- | --- |
| `TELEGRAM_NOT_CONFIGURED` | Проверить обе переменные в `.env` и папку запуска. |
| `TELEGRAM_TOKEN_INVALID` | Проверить токен BotFather без префикса `bot` или URL. |
| `TELEGRAM_CHAT_NOT_FOUND` | Проверить ID получателя и нажать Start у этого бота. |
| `TELEGRAM_FORBIDDEN` | Разблокировать бота; проверить права в группе или канале. |
| `TELEGRAM_CHAT_MIGRATED` | Указать новый ID супергруппы. |
| `TELEGRAM_NETWORK`, `TELEGRAM_TIMEOUT` | Проверить доступ Node.js к `api.telegram.org`, сеть и прокси. |
| `TELEGRAM_RATE_LIMIT` | Подождать перед повтором. |

Если Telegram доступен, а форма не получает ответ сервера, открывайте сайт от `npm start`, а не файл HTML, Live Server или GitHub Pages.

### Windows cmd и локальный HTTP-прокси

Если прямое соединение недоступно, перед запуском используйте доверенный локальный HTTP-прокси. Для Node.js 24.0+ или 22.21+ и прокси на `127.0.0.1:10809` без авторизации:

```cmd
set "HTTPS_PROXY=http://127.0.0.1:10809"
set "HTTP_PROXY=http://127.0.0.1:10809"
set "NO_PROXY=localhost,127.0.0.1,::1"
set "NODE_USE_ENV_PROXY=1"
npm run telegram:check
npm start
```

Замените порт на фактический и держите прокси включённым. Настройки действуют только в этом окне cmd. Ядро рабочего VPN менять не требуется.

## Публикация

GitHub Pages раздаёт только статические файлы и не запускает Node.js. При пустом `endpoint` в `form-config.js` форма копирует заявку в буфер. Слияние ветки само по себе не включает доставку в Telegram на Pages.

Для доставки с опубликованного сайта разместите обработчик на публичном HTTPS-сервере:

1. Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в окружении сервера.
2. Добавьте точный origin сайта в `ALLOWED_ORIGINS`, например `https://baba4kih.github.io` — без пути и завершающего слеша.
3. Укажите только адрес API в публичном `form-config.js`:

   ```js
   window.EE_FORM_CONFIG = { endpoint: 'https://YOUR-BACKEND.example/api/brief' };
   ```

Можно разместить весь сайт на том же сервере через `npm start`. Для контейнера может понадобиться `HOST=0.0.0.0`; HTTPS обеспечивает платформа или reverse proxy. Telegram webhook для отправки заявок не нужен.

Сервер проверяет согласие, honeypot, типы и длины полей, ограничивает JSON до 16 КБ и частоту до 5 запросов в минуту с IP. Лимит хранится в памяти процесса. За reverse proxy он применяется к адресу прокси: настройте ограничение по реальному IP на платформе. CORS не заменяет защиту от ботов.

Политика и согласие пока содержат заглушки. Перед приёмом реальных данных заполните документы под фактическую обработку и доставку в Telegram; галочка и отметка времени не заменяют учёт согласий.

## Поиск и превью ссылок

Публичный адрес: https://baba4kih.github.io/EditEffects./. Главная содержит canonical, описание, JSON-LD, Open Graph и Twitter Card; изображение `og-image.png` имеет размер 1200×630. В `sitemap.xml` включена только главная. Страницы-заглушки документов имеют `noindex, follow`; после заполнения документов это ограничение можно пересмотреть.

### Подтверждение прав в поисковых системах

«SEO-сертификат» обычно означает подтверждение владения сайтом. Для него нужен персональный метатег от выбранного сервиса; SEO-разметка сама по себе не подтверждает права.

1. В Google Search Console добавьте ресурс с префиксом URL `https://baba4kih.github.io/EditEffects./` и выберите подтверждение HTML-тегом.
2. В Яндекс Вебмастере добавьте сайт и откройте подтверждение прав через метатег. Если сервис требует владение всем `baba4kih.github.io`, подтверждение надо разместить на главной этого поддомена в репозитории `Baba4KiH.github.io`, а не выдумывать код для папки проекта.
3. Передайте выданные метатеги `google-site-verification` и `yandex-verification` для добавления в `<head>` главной; это публичные коды, пароли не нужны. После публикации нажмите «Подтвердить» в соответствующем сервисе. Не удаляйте действующие метатеги после проверки.
4. После подтверждения добавьте карту `https://baba4kih.github.io/EditEffects./sitemap.xml` в кабинет поисковика и запросите переобход главной.

`robots.txt` должен находиться в корне поддомена (`https://baba4kih.github.io/robots.txt`). Файл внутри `/EditEffects./` не управляет обходом проекта, поэтому здесь он не добавлен. Для проверки и изменения корневого robots.txt нужен отдельный репозиторий сайта пользователя. Индексация и вид превью определяются поисковиками и соцсетями; обновления могут кэшироваться.

При переезде на свой домен обновите canonical, Open Graph URL/изображение, JSON-LD и sitemap, а также адреса ресурсов в кабинетах поисковых систем. HTTPS-сертификат управляется хостингом и не заменяется метатегами.
